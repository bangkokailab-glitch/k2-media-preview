# K2 Family Office 記事詳細の基本型

2026-10-26 構成確認用。対象は `layout: editorial`、`template: editorial-v2` の記事。
著者紹介はカード型を採用し、横並びカードを基準表示する。名刺カード・中央配置カードは比較案。

## 固定する順番

| 順番 | 部品 | 役割・運用 |
|---|---|---|
| 1 | H1・メイン画像 | 記事タイトルと記事データの写真 |
| 2 | 導入文 | 読者の状況や問題を示す。既存の「多くの経営者にとって…」を使用 |
| 3 | 会話の吹き出し | 読者の疑問とK2側の回答。顔写真ではなく既存のK2ロゴを使用 |
| 4 | NOTE | 最初に押さえる視点を短く示す情報枠。クリックするボタンではない |
| 5 | ガイドバナー | 既存の「ファミリーオフィスを知る」画像 |
| 6 | 目次 | 本文H2/H3とまとめH2から自動生成。クリックで見出しへ移動 |
| 7 | H2・本文・H3・本文 | 話題ごとに構成。必要な箇所で注意喚起・NOTE・会話を挿入できる |
| 8 | まとめH2 | 記事を締める見出し |
| 9 | まとめの会話 | 読者が持ち帰る疑問に吹き出しで答える |
| 10 | まとめ本文 | 本文の内容を整理する |
| 11 | 最後のNOTE | 判断の際に残しておきたい補足 |
| 12 | KEY POINT | 記事全体の要点を3点程度に整理 |
| 13 | ガイドへの短い案内文・ボタン | KEY POINTの直後、記事本文内に置く。記事の内容に合うガイドへつなぐ |
| 14 | 著者情報・関連記事 | 本文外の既存領域 |

## 本文データの編集

`assets/articles.js` の対象記事を編集する。HTML文字列を本文に入れず、以下のデータを使う。

- `introParagraphs`: 導入文の段落配列。
- `openingBlocks`: 冒頭の会話（`qa`）と補足（`note`）。
- `sections[]`: `id`、`title`（H2）、`blocks[]`（本文）。
- `summary`: `id: summary`、`title`（まとめH2）、会話→本文→NOTEの`blocks[]`。
- `points`: KEY POINTの文字列配列。
- `blocks.type`: `paragraph` / `heading`（H3） / `qa` / `risk-list` / `note`。
- H3には重複しない`id`を付ける。未指定の場合は部品側で付与する。
- 目次・検索対象は本文データから生成する。見出し変更時に別の目次原稿を直す必要はない。

## ガイドボタンの文章・リンクをHTMLで変更する

各記事の `index.html` にある `<template id="article-guide-action">` が編集箇所。
JSを直さず、案内文・ボタン名・リンク先を記事ごとに変更できる。画像に文字を焼き込まない。

```html
<template id="article-guide-action">
  <aside class="article-guide-action" aria-label="ガイドでさらに読む">
    <p class="guide-action-copy">この記事から自然につながる案内文</p>
    <a class="guide-action-link" href="#guide" data-pending="guide" data-guide-page="01">
      案内するガイドに合わせたボタンの文言
    </a>
  </aside>
</template>
```

ガイド01・02・03に合わせて `data-guide-page` を変更する。現時点ではガイドの本番URLが未確定のため案内ダイアログを表示する。URL確定時は `href` を実際のURLへ変更し、`data-pending="guide"` を外す。存在しないURLや未採用のデザイン案には勝手につながない。

`build.mjs`は各記事の既存templateを保持する。新しい記事には `templates/article-guide-action.html` を初期値として配置するため、初期値を記事に合わせて編集する。

## 表示上のルール

- 本文の最大幅620px。本文・役職・リンク・注記は15px以上。英語ラベルは既存サイズを維持。
- 著者写真は48〜72px程度で、文字を中心に構成する。
- 本文末のCTAは小さな案内文とボタン。記事の途中に大きな販売用セクションを持ち込まない。
- 本文・まとめの追加文は型の確認用文案。原文の金融・税務表現を正式掲載する前に別途原稿確認する。
